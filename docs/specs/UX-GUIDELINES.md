# UX 規格 — 任務過程教學體驗

> 版本：v0.1 草稿 ／ 日期：2026-10-24 ／ 狀態：待與產品規劃團隊對齊
> 範圍：學員前台（P1–P7）的**教學過程體驗**。不改教學規則（兩關、方案確認、完成判定看實際結果），只改呈現與引導。
> 依據：POC 站台實際體驗（`docs/design/poc-screenshots/README.md`）。**POC 的 UI/UX 不沿用**（使用者 2026-10-24 決定），本文件是我方重新設計的起點。
> 視覺風格、色彩、字型屬 Design System（PRD 21，尚未產出），本文件不涉及。

## 1. 設計原則

| # | 原則 | 說明 |
| - | ---- | ---- |
| 1 | **每個時刻只問一件事** | 學員任何時候都能回答「我現在該做什麼」 |
| 2 | **等待要有進度感** | 任何超過 3 秒的操作都要說明在做什麼、大概還要多久 |
| 3 | **教學跟著流程出現** | 提示在需要的時刻主動出現，而不是藏在彈窗等學員去找 |
| 4 | **細節可展開，預設簡潔** | 資訊分層，不一次全給 |
| 5 | **犯錯是學習的一部分** | 不計分、不責備；失敗與阻擋都給繁中說明和下一步 |
| 6 | **手機也能完整完成** | 四種螢幕尺寸都能做完全部操作（OV-02） |

## 2. POC 觀察到的痛點

| # | 痛點 | 證據 |
| - | ---- | ---- |
| P-1 | Agent 執行沒有進度感 | 出方案超過 10 分鐘，期間只有「Agent 正在處理…」與「模擬查詢與操作 · N 筆」 |
| P-2 | 資訊一次全給 | 三欄同時展開，7 個系統卡、4 個面板、很長的任務卡 |
| P-3 | 教學提示藏在彈窗 | 「需要協助？」內有起始 Prompt 與 13 條提示，要自己點開 |
| P-4 | 回饋都在事後 | 做錯要到提交報告才知道 |
| P-5 | 方案卡資訊密度高 | 動作、選項、執行條件、停止條件同卡呈現 |
| P-6 | 錯誤外洩英文 | Studio 顯示 `ModelHTTPError` |
| P-7 | 情境事件（動態插入的新消息）出現得突然 | 執行中 Agent 暫停並出現「情境消息」，學員需自己判斷要不要告訴 Agent |

## 3. 規格項目

優先級：**M1** = MVP1 必做｜**M2** = MVP2｜依 2 人團隊容量，M1 以最少項目為限。

### U-1 執行進度說人話【M1】

- Agent 執行時，對話區顯示**步驟條**，每一步是學員看得懂的一句話，例如：「正在查詢王○明的掛號」→「正在核對院內規則」→「正在擬定方案」。
- 顯示已經過時間；若後端可估計，顯示預估剩餘時間。
- 原始的「N 筆查詢與操作」仍保留，放進「執行與確認紀錄」供查證。
- 超過閾值（建議 60 秒，待定）仍無結果時，顯示「還在處理，您可以先看看任務清單」並提供「停止」。

**驗收**：
- 成功：執行中每個階段切換，步驟條在 2 秒內更新。
- 失敗：Agent 或 LLM 逾時 → 繁中說明＋「再試一次」，輸入內容不遺失；不顯示任何英文錯誤字串。
- 隔離：A 學員的進度事件不會出現在 B 學員的畫面。

**後端依賴**：Layer 4 的 SSE 事件要有階段事件（見 §4）。

### U-2 分階段揭露【M1】

- 第一次進入 P5：只顯示「你的任務」摘要與對話輸入框；系統面板收合為一列小圖示。
- Agent 用到某系統時，該系統圖示亮起並可點開查看（沿用「查看不觸發操作」的規則，並明確標示）。
- 任務完整內容、Agent 的界線、操作提示改為**可展開的抽屜**，預設收合。
- 手機版改為單一時間軸（任務 → 對話 → 結果），不再用三個頁籤切換。

**驗收**：新學員首屏不超過 3 個主要區塊；四種尺寸皆可完成全流程。

### U-3 任務清單取代長文【M1】

- 把「怎樣算完成」變成**可勾選的清單**：每位分派對象一項、提交報告一項。
- 項目隨 Agent 結果與實際系統狀態**自動更新**（以模擬系統的實際結果為準，不是 Agent 說了算）。
- 狀態：未開始 / 進行中 / 需你處理 / 已完成 / 已交接。

**驗收**：Agent 回報「已完成」但模擬系統查無結果 → 清單不得打勾，並提示「以系統查證為準」。

### U-4 情境化提示【M2】

- 在關鍵時刻主動出現一句提示，可關閉、可在設定中全部關閉：
  - 方案卡出現時：「先核對身分、看選項，再按同意」
  - 學員按「同意」前：顯示將會發生什麼（聯絡誰、改什麼）
  - 情境事件出現時：「這是新消息，Agent 不知道，要不要告訴它由你決定」
- 提示內容來自情境包（由內容管理員維護），不寫死在程式。

### U-5 方案卡分層【M1】

- 預設層：**對象 / 要做什麼 / 要你確認什麼**，加上「同意 / 不同意 / 修改」。
- 展開層：可提供的選項、執行條件、停止條件。
- 風險動作（聯絡真人、寫入系統、發通知）以標籤標出，並說明「同意後 Agent 只在此範圍內執行」。
- 學員可以在確認前向 Agent 提問，方案保留。

### U-6 查證引導【M2】

- Agent 每次引用規則或資料時，附上可點開的依據（例如規則編號）。
- 輕量提示學員查證，例如「Agent 查了 POL-REBOOK-AUTH，點開看依據」。不計分、不判對錯。

### U-7 情境事件呈現【M1，沿用 POC 機制】

- POC 有動態情境事件：執行中插入新消息，Agent 暫停且**收不到**該消息，學員決定是否告知。這是好的教學設計，保留。
- 呈現改進：事件以醒目的卡片出現在對話區，標示時間與「只有你看得到」，並提供三個明確選項（告訴 Agent 並重新規劃 / 照原方案繼續 / 先問問題），而不是只靠輸入「繼續」。
- 事件由情境包定義（時機、內容），後台動態管理。

### U-8 友善的失敗與阻擋【M1】

- 所有錯誤訊息繁體中文，說明「發生什麼、你可以做什麼」。
- 用量用盡：區分「你的額度用完」與「整體額度用完」，仍可登入並查看既有成果。
- 外部服務（模擬系統、LLM）不可用：顯示等待說明與重試；不得出現英文技術字串。
- 重設本案：二次確認，說明「案件資料回到初始，Skill 與學習紀錄保留」。

### U-9 登入體驗【M1，依已決定的規則】

- 已註冊 email：只輸入 email → 提示「登入連結已寄出，10 分鐘內有效，僅能使用一次」。
- 未註冊 email：輸入邀請碼與顯示名稱後註冊。
- 對未註冊與已註冊 email 顯示一致訊息（避免洩漏帳號是否存在）。
- 因寄信每分鐘輪詢，頁面提示「約 1–2 分鐘內收到」，並提供「重新寄送」（限流）。
- 連結過期或已使用：繁中說明並引導重新寄送。

### U-10 使用教學【靜態頁與互動導覽 M1；動畫 M2】

使用者 2026-10-24 提出需要「簡單的使用教學頁面或動畫」。依 2 人團隊容量，分三層：

| 層 | 內容 | 階段 |
| -- | ---- | ---- |
| 靜態教學頁 `/guide` | 圖文三步（交代任務 → 確認方案 → 寫成 Skill）、「Agent 的界線」、常見問題、第二關與換案驗證的說明；登入前後都能看 | M1 |
| 首次互動導覽 | 第一次進 P5 時以高亮標示輸入框、任務清單、系統面板、方案卡；可跳過、可從頁首「使用說明」重看；已看過的狀態存在帳號上（跨裝置一致） | M1 |
| 短動畫（30–60 秒） | 展示完整流程；放在教學頁與登入頁；建議由產品規劃團隊提供腳本與素材 | M2 |

**驗收**：
- 成功：新學員第一次進 P5 自動出現導覽；跳過後不再自動出現；頁首「使用說明」隨時可重看。
- 失敗：導覽的目標元素不存在（例如手機版版面不同）→ 自動略過該步，不卡住流程；教學頁資源載入失敗 → 顯示文字版內容。
- 四種尺寸都能完整看完導覽；全站繁體中文。

**內容來源**：教學文字與步驟由產品規劃團隊提供或確認（POC 現有「開場說明」「工作台導覽」可當參考，不直接沿用其 UI）。

### U-11 情境視覺素材（後台動態設定）【最小版 M1；完整 M2】

使用者 2026-10-24 提出：依情境提供不同的示意圖或底圖，由後台設定上架，讓前台更豐富、更有彈性。

**原則**：素材是**情境版本的一部分**；只開放有限的「插圖位置」，**不開放版面與 CSS**，確保教學流程（任務、對話、方案卡）在每個情境一致。

| 位置 | 用途 | 階段 |
| ---- | ---- | ---- |
| 情境卡封面 | P3 / P4 的卡片 | M1 |
| 工作台橫幅或底圖 | P5 頂部，營造情境氛圍 | M1 |
| 產業預設圖 | 沒上傳時的後備圖 | M1 |
| 人物與場景插圖 | 任務說明、情境事件卡 | M2 |
| 模擬系統圖示 | 右側系統面板 | M2 |
| 主題強調色 | 從設計系統的色票中選，不自訂 | M2 |

**規則**：
- 只收點陣圖（不收 SVG，避免腳本注入）；限制檔案大小與尺寸；每張必填**替代文字**。
- 每個位置定義手機與桌機的裁切方式，後台上傳時預覽四種尺寸。
- 文字蓋在圖上時自動加遮罩，確保對比足夠。
- 素材跟著情境版本；更新情境產生新版本，已開始的練習維持舊素材。
- 圖片載入失敗或未上傳 → 顯示產業預設圖，不影響流程。

**驗收**：
- 成功：後台上傳封面與橫幅後，P3 / P4 / P5 顯示該圖；四種尺寸無破版。
- 失敗：檔案過大 / 格式不符 / 缺替代文字 → 後台拒絕並說明原因；圖片載入逾時 → 前台顯示預設圖，不顯示英文錯誤。
- 隔離：A 情境的素材不會出現在 B 情境。

**依賴**：**NAS**（使用者 2026-10-24：架構已有 NAS，取代先前假設的物件儲存），目錄規約見 `nas/README.md`；是否另有 CDN 待確認。素材來源（產品規劃師提供或 AI 生成）與版權待確認。

## 4. 後端需配合的事件格式（Layer 4 設計輸入）

為了支撐 U-1、U-3、U-7，SSE 事件建議至少包含下列類型（欄位於 Layer 4 開始前定案）：

| 事件 | 用途 | 主要欄位 |
| ---- | ---- | -------- |
| `phase` | 階段切換（對應步驟條） | 階段代碼、學員可讀文字、開始時間 |
| `tool_call` | 查詢或操作（對應紀錄） | 系統、動作、狀態（進行中 / 完成 / 失敗） |
| `plan` | 方案卡 | 對象、動作、選項、條件、風險標籤 |
| `scenario_event` | 情境事件 | 時間、內容、可選處置 |
| `task_progress` | 任務清單更新 | 項目、狀態、依據（系統實際結果） |
| `error` | 錯誤 | **繁中訊息**、可重試與否（不含英文堆疊） |

## 5. 優先順序與工時影響

| 項目 | 階段 | 備註 |
| ---- | ---- | ---- |
| U-1、U-2、U-3、U-5、U-7、U-8、U-9 | M1 | 與 Layer 4、5 一起做；工時已大致涵蓋在 P5 的 XL 估算內，但 U-1 與 U-3 需後端事件配合 |
| U-10 靜態教學頁與首次互動導覽 | M1 | 教學頁低成本；互動導覽需「已看過」旗標存帳號 |
| U-11 封面、橫幅、產業預設圖 | M1 | 需物件儲存；工作量小但有基礎設施依賴 |
| U-10 短動畫、U-11 其餘位置、U-4、U-6 | M2 | 價值高但非必要 |

> 2 人團隊下，MVP1 若走「垂直切片」（只做 med-01），U-7 的情境事件仍建議保留，因為它是 med-01 本身的教學設計。
