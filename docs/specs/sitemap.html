學員主流程

P1 登入→曾開始情境？是→P2 我的學習／否→P3 探索 →P4 情境→P5 第一關→（完成）P6 第二關→P7 成果

規則：第一關完成前不能進 P6；隨時可在 P2 / P3 / P7 切換；進行中情境可在 P5 / P6 間切換。「繼續學習」依狀態接回 P5、P6 或進行中的換案測試。

階段說明
M1MVP1 就有後台畫面（單一「管理員」角色）：A0 殼與登入、A1 帳號與邀請碼、A2 情境管理（動態新增 / 編輯 / 上下線、上傳素材到 NAS）、A3 用量與使用紀錄、A4 稽核紀錄。詳見 docs/design/MVP1-SCOPE.md
M2後台最小版：取代 CLI（帳號與邀請碼、情境管理、用量、系統健康、稽核）
M3完整版：多組織、授權、模型目錄、成效分析（依 POC 的 Org / Seat / Role / Credits 提案，討論版）

MVP1 管理後台（單一管理員角色，這是 11 月底要交付的）

  • A0後台殼與 admin 登入 M1只有一個 admin 帳號、帳密登入（不走 email 連結）；開發期密碼固定，雲端部署前必須更換
  • A1帳號與邀請碼 M1產生 / 停用邀請碼與使用狀況；帳號停用啟用；demo 帳號；個別用量上限
  • A2情境管理 M1新增、編輯（新版本）、上下線；上線前檢查；上傳封面與橫幅（NAS）；預覽
  • A3用量與使用紀錄 M1每人每日用量、使用中人數、失敗紀錄、進度摘要（不含對話逐字稿）
  • A4稽核紀錄 M1管理操作只增不改

下方「系統後台 / Org 後台」是 POC 提案的完整版（多組織、Seat、Credits、模型目錄），屬 MVP2 以後，MVP1 只預留資料欄位。

系統後台（System Admin）— MVP2 以後

  • Y1平台概況 M2 簡版M3
  • Y2Org 管理 M2 最小建立 / 停用 Org、Owner、Seat 數、Credits 池
  • Y3Credits 與成本 M3
  • Y4模型目錄 M3LLM 現況：Gemini API
  • Y5訓練營運（漏斗、卡關點） M3
  • Y6情境管理 / 內容營運 M1 = A2 動態新增、編輯（新版本）、上下線；上傳封面與橫幅（NAS）；上線前檢查結果
  • Y7系統健康 M2Agent、Twin、LLM 錯誤率與延遲
  • Y8稽核紀錄 M2 起只增不改
  • Y9支援工具 M1 = A1邀請碼、demo 帳號、個別用量上限；重設案件、以 User 身分檢視（M2，留稽核）

Org 後台（Org Owner / Admin / Producer）— MVP2 以後

  • O1概況 M3Seat 使用、待接受邀請、Credits
  • O2成員與 Seat M2 最小邀請 / 停用、分配 Seat、指派角色
  • O3Credits 與個人上限 M3
  • O4模型：核准清單與預設 M3
  • O5學習進度（不含對話逐字稿） M2
  • O6情境與發布（Producer） M3對應 Studio 發布到自己 Org

角色

System Admin平台維運，不屬任何 Org
Org Owner / Admin管理自己 Org 的成員、Seat、上限
Producer建立與發布自己 Org 的情境
平台工程師M1 以 CLI 代替後台畫面

隱私：Org Admin 看不到學員對話逐字稿；System Admin 預設也不能讀。
