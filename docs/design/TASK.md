## Layer 1：基礎建設與資料層

**UC 範圍**：UC-ACT 3.1.1.1 ～ 3.1.2.2

**目標**：K8s 上雲的環境、CI/CD、PostgreSQL / Redis、核心 Schema 與 migration 機制，讓後續 Layer 能在真實環境部署與測試。

**驗收條件**：
| UC 編號 | 功能 | 成功路徑 | 失敗路徑 |
| ------- | ---- | -------- | -------- |
| UC-ACT 3.1.1.1 | K8s 環境與 CI/CD | push 後自動 build、部署到 dev namespace，`/healthz` 回 200 | build 失敗 → 不部署且通知；部署後 healthz 失敗 → 自動回滾 |
| UC-ACT 3.1.1.2 | PostgreSQL 與 Redis 佈署 | api 連得到兩者 | 連線失敗 → healthz 回 503 且帶明確元件名，不拋 exception |

## Layer 2：身分與帳號

**UC 範圍**：MVP1：UC-ACT 3.2.1、3.3.1、3.4.1.1、4.3.3；MVP2：4.3.1、4.3.2（SSO）

**目標**：email 為帳號；**MVP1 登入流程（2026-10-24 使用者決定）：輸入邀請碼與 email → 驗證後寄 token 到信箱 → 以 token 登入**；首次註冊需邀請碼與顯示名稱。Google / Microsoft SSO（UC 4.3.1、4.3.2）暫移 MVP2，同 email 跨方式視為同一帳號的規則於加入 SSO 時驗收。token 形式（連結或驗證碼）、有效期、是否綁定邀請碼待確認。

**驗收條件**：
| UC 編號 | 功能 | 成功路徑 | 失敗路徑 |
| ------- | ---- | -------- | -------- |
| UC-ACT 3.3.1.1 | email 驗證與 token 登入（邀請碼 + email → 寄 token） | 寄出連結，點擊後登入 | 連結過期 / 已使用 → 繁中說明，不登入；寄信服務失敗 → 繁中提示可重試，不洩漏內部錯誤 |
| UC-ACT 3.3.1.2 | 邀請碼註冊 | 有效邀請碼 + 顯示名稱 → 建立帳號並歸屬預設組織 | 邀請碼無效 / 已用 / 過期 → 拒絕，不建立帳號 |
| UC-ACT 3.3.1.3 | Session 與帳號合併 | 先 magic link 後 Google，登入同一帳號、學習紀錄不分散 | 未登入呼叫受保護 API → 401；Session 過期 → 401 |
| UC-ACT 4.3.1 / 4.3.2（**MVP2**） | Google / Microsoft SSO | 授權成功登入 | 使用者取消授權 / IdP 逾時 / IdP 回 5xx → 回登入頁並顯示繁中訊息，不拋 exception |
| UC-ACT 4.3.3 | 寄信 | 信件為繁體中文 | 寄信 API 逾時或連線失敗（兩種 sibling）皆被攔住 |
| UC-ACT 3.4.1.1 | 邀請碼 CLI | 工程師產生邀請碼與 demo 帳號 | 重複建立 → 明確錯誤，不產生重複資料 |

## Layer 3：情境包與 Digital Twin 串接

**UC 範圍**：UC-ACT 3.3.2、3.4.2.x、4.1.1 ～ 4.1.3

**目標**：定義情境包規格並載入；串接 Orbit Digital Twin（先醫療業），支援每位學員獨立的 sandbox 與重設。

**驗收條件**：

| ------- | ---- | -------- | -------- |
| UC-ACT 3.4.2.1 | 情境包規格與載入 | med-01 原案可載入並開一次練習 | 缺必要欄位 → 載入失敗並指出欄位；未標課程等級 → 不能上線（OV-06） |
| UC-ACT 3.4.2.2 | 上線前檢查 | 劇本提到的資料在 Twin 找得到才放行 | 找不到 → 不放行並列出缺哪筆 |
